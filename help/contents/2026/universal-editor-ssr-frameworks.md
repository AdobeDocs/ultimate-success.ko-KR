# 범용 편집기 및 최신 SSR 프레임워크를 사용하여 빠르고 편집 가능한 사이트

최신 웹 팀은 마케터를 위한 컨텍스트 내 편집의 영향을 받지 않고 헤드리스 및 최신 JavaScript 프레임워크의 자유를 원했습니다. 이 세션에서는 Adobe Experience Manager Universal Editor 및 최신 SSR(서버측 렌더링) 프레임워크(예: React 및 Next.js 스타일 설정)가 작성자가 시각적으로 여전히 편집할 수 있는 빠른 SEO(검색 엔진 최적화) 사이트를 제공하는 방법을 보여드렸습니다. Universal Editor를 프레임워크 기반 앱으로 연결하는 방법, SSR이 성능과 Core Web Vitals에 영향을 미치는 방법 및 작성자가 프런트 엔드를 중단하지 않고 경험을 안전하게 업데이트할 수 있도록 구성 요소를 구성하는 방법에 대해 설명했습니다. Adobe Experience Manager(AEM) 또는 Edge Delivery Services(EDS) 프로젝트를 계획하거나 현대화하는 경우 이 웨비나는 즉시 사용할 수 있는 실용적인 블루프린트를 제공했습니다.

>[!VIDEO](https://video.tv.adobe.com/v/3491408/?learn=on&enablevpops)

## 주요 학습 사항

* **표준 EDS 사이트와 사용자 지정 SSR 프레임워크를 사용하는 경우**
표준 Adobe Experience Manager Edge Delivery Services(EDS) 사이트가 대부분의 프로젝트에 가장 적합한 기본값인 이유와 유니버설 편집기를 재구축하는 대신 기존 앱(예: 상점 또는 포털)에 계층화하는 것이 적절한지 확인했습니다.

* **유니버설 편집기가 EDS와 기존 프레임워크 모두에 연결된 방법**
유니버설 편집기가 일반적인 AEM EDS 설정에 어떻게 적합한지, 그리고 이미 프로덕션에 있는 React 또는 Next.js 스타일 SSR 애플리케이션에 연결할 때 동일한 개념이 어떻게 적용되는지 보았습니다.

* 성능 및 SEO 요구 사항에 따라 균형 조정된 EDS 기본값을 계산하는 **SSR**
EDS 기본값을 사용하고 제품 세부 사항 또는 랜딩 페이지와 같은 가치가 높은 페이지의 경우 SEO 및 Core Web Vitals에 미치는 영향을 포함하여 특정 경험에 대해 SSR(사용자 정의 서버 측 렌더링)이 실제로 필요한 시기를 파악했습니다.

* **개발자 및 마케터용 앱 패턴을 손상시키지 않은 작성**
개발자가 유지 관리 가능한 코드베이스를 깔끔하게 유지하면서 작성자에게 표준 EDS 사이트에서든 기존 프레임워크와 통합하든 상관없이 컨텍스트 내 편집 기능을 제공하는 구성 요소 및 콘텐츠 모델 패턴을 발견했습니다.
